# PPSB｜互换候选变体与品类叙事边界

> 日期：2026-08-11  
> 性质：结构与方向登记（F-P，记录裁决本身，不是行为证据）  
> 状态：互换为候选变体（H）；当前赠礼版主线不变

## 一、互换变体

“互换”登记为赠礼版的候选变体，等级为 H。

其产品单位是：同组多人各自制作一个自己的形象，再彼此交换；每位参与者最终收到多个不同人物的实体。它不同于当前主线“一个人制作自己的形象，复制 N 件后送给不同接收者”。

互换可能改变接收者面对的对象：从单独摆放一个他人的形象，变为摆放一组共同关系成员。该变化是否降低尴尬、增加纪念感或提高实际摆放，均为 H，当前没有行为材料。

互换不升为主线，也不替代当前产品单位。

## 二、成本边界

当前只能确认结构差异：主线包含 1 个独立人物模型和 N 件复制品；互换包含 N 个独立人物模型，且每个模型需要制作多少件取决于参与人数与交换方式。

不能据此直接写成“成本必然按人数线性增加”。自动化程度、人工修型、不同模型的批量减免、打印排版与订单合并方式均未取得报价。互换的真实总成本、每人价格与毛利口径当前为 Ø，须由统一规格询价或实际报价关闭。

墓碑分析中的“按人线性成本”可作为风险提示，不能在未取得同位报价前直接判定互换已经与该死法同构。

## 三、验证纪律

互换只作为自然出现的候选条件记录，不主动向参与者或客户推介，也不询问“愿不愿意互换”。

若参与者、付款人、发起人或接收者自发提出“每人做一个、互相交换”或同义方案，记录原话、角色、提出时机、人物数量、每个模型的件数与报价变化。自发提出只构成行为线索，不证明付款、接收或摆放成立。

公开观察只能记录原始页面中已经出现的多人各自形象与互换情形。无法确认人物关系、制作方式或是否互换时写“未知”，不得根据一张多人摆放图片自行补全关系。

## 四、未恢复的判断

“时间系列”不在本轮登记为复购结构。写真、纪念册、肖像画、定制插画等相邻品类最多提供 I 级机制线索，不能替代 PPSB 的接收者行为、重复付款或复购事实。

当前复购引擎继续为空。本条不是永久否决时间系列，只是不以类比材料恢复被撤回的判断。

## 五、品类叙事分账

“雕像民主化”“保存本体而非痕迹”“柯达时刻”“对抗遗忘”等表述，本轮不进入 README、可行性分析报告、商业计划书或产品成立结论。

原因不是这些表达已经被证明错误，而是它们不能关闭当前关键空格：独立客户是否付款、接收者是否接受、是否实际摆放、两周后是否仍在原位，以及实体相对照片或其他纪念品的溢价理由。

此类表达可以作为讨论或对外叙事草案，但不得作为需求、差异化、复购或品类成立的证据。

README 中“能摆在桌上的实体”本轮按物理形态描述理解，不解释为接收者已经发生实际摆放，因此不修改。

## 七、购买频率与增长术语

本品类的真实购买频率当前为 Ø。毕业场景低频不能推出全部告别、纪念或关系赠礼场景低频，不得写成“低频是品类固有属性”。在首笔独立付款和完整赠送闭环出现前，复购引擎继续为空，不以新功能填补。

后续记录使用四个分开的术语：

- 订单扩展：同一付款人在同一赠送场景中追加件数，尚未形成新的购买场景；
- 复购：上一订单结束后，同一付款人在新的场景再次购买；
- 转介绍：接触过产品的人引入新的独立付款人，介绍者自己不必付款；
- 接收者转化：原接收者后来成为新的付款人。

四类行为不得合并计数，也不得用订单扩展填补复购。

## 八、接收者转化候选链路

接收者收到实体、形成记忆、后来出现自己的赠礼场景并独立付款，登记为候选获客链路，等级为 H。四个环节分别记录，任何一环都不能替代其余环节。

当前 TASK-003 R1 只找到一条接收者转为买家的公开痕迹，且推广污染不能排除。接收者转化仍为 Ø，不得据此宣称裂变自然成立、传播具有病毒性或获客成本较低。

轻量软件中的回复或分享，与重新发起一笔需要资料提交、设计确认、付款和实体履约的订单不同构。该结构差异不依赖当前仍为空的价格和交期数字，也不能用来预判转化一定失败。

## 九、二维码候选分账

二维码反馈与二维码自助体验是两个候选，不得混写。

二维码反馈指接收者在明确邀请下自行留下反应。它登记为候选取证装置，等级为 H，不是增长机制。若实际发生，所得内容等级上限为 I，不能证明自然摆放、自然需求或付款。未扫码一律记为“未知”，不得解释为拒绝；未确认接收者实际收件时，不得用发码数量作为分母，不计算扫码率或回应率。

二维码自助体验指接收者尝试生成自己的数字预览。它登记为候选免费体验步骤，等级为 H。该步骤可能增加体验，也可能增加操作负担；不能预设它缩短接收者转化链路。免费生成不等于付款，也不等于实体需求。

两个候选均未获执行授权。启动前须分别确认告知、肖像同意、资料收集、保存与删除、是否形成接收者名单，以及与 TASK-003 接收者边界的关系。二维码自助体验还依赖 TASK-012 授权项 2 的实际记录。

## 十、“心中的自己”框架候选

“用户定义自己想表达的形象，而不只追求照片还原”登记为框架候选，等级为 H。当前不得称为个人形象资产；持久保存、跨载体复用、版本管理、权利归属与再次付费均未验证。

该框架不改变当前产品单位。当前主线仍是一人制作自己的形象并复制 N 件送给不同接收者。制作人认可与熟悉他的接收者能认出仍是两条独立标准，不因“心中的自己”而自动降低接收者识别要求。

TASK-012 增加一条待验问题：普通用户能否表达偏离照片还原的主动选择，还是只能要求“再像一点”。若未来把可复用的个人形象本身作为核心、把赠礼降为应用之一，属于产品与公司形态切换，须另行裁决，不得写成当前路线的自然升级。
